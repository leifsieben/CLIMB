# REPRODUCE.md — one-stop reproduction guide

Every figure and table in the paper is generated by `climb_figures.ipynb` from the eval outputs in
`figure_data/`, which are in turn produced by `eval_v2.py` from the model checkpoints. This file maps
**figure → notebook cell → data wave → exact command**, and states what a reviewer needs to obtain.

There are two ways to reproduce, cheapest first:

- **Path A — regenerate the figures from the results** (minutes, CPU). Get `figure_data/`, run the
  notebook, verify against the committed manifest. No GPU, no checkpoints.
- **Path B — reproduce the results from the checkpoints** (hours, GPU). Get the encoders, re-run
  `eval_v2.py` to rebuild `figure_data/`, then do Path A.

---

## 0. Get the artifacts (the access gate)

`figure_data/` (~17 GB of results) and the encoder checkpoints (~12 GB) are **git-ignored** — the repo
ships code, the executed notebook, and `figure_data_manifest.json` (a content fingerprint), but **not**
the data. To reproduce you must obtain:

| Artifact | Hugging Face (public) | Working S3 location (private) |
|---|---|---|
| **Checkpoints** (+ byte-BPE tokenizer) | `<org>/climb-encoders` (model) | `s3://climb-s3-bucket/experiments/<wave>/<run>/encoder/`, `.../tokenizer_10M/` |
| **Raw results** (`figure_data/`) | `<org>/climb-results` (dataset) | `s3://climb-s3-bucket/experiments/<wave>/<run>/` |
| **Pre-training data** (corpus, descriptors, SFT table, blocklist) | `<org>/climb-pretrain-data` (dataset) | `s3://climb-s3-bucket/tokenized*/`, `.../configs/` |

> **Reviewers:** until the public archive above is live, reproduction needs read access to the S3
> bucket. Request it from the authors. Everything below assumes the artifacts are placed at the paths
> `figure_data/<wave>/<run>/...` and `figure_data/_tokenizer/` (the layout the notebook expects).

Per-run S3 layout: `<wave>/<run>/{encoder/model.safetensors, metrics.jsonl, moleculenet/, moleculenet_cv/}`
where `moleculenet*/` hold `suite_summary.json` + per-molecule `test_predictions.csv`.

## 1. Figure → cell → wave → eval command

Notebook cells are 0-indexed as in `climb_figures.ipynb`. Standard 6-task set:
`ESOL BBBP BACE Tox21 QM7 HIV`. Tokenizer: `figure_data/_tokenizer`.

| Figure / table (file) | Cell | Wave(s) read | Eval scheme |
|---|---|---|---|
| `figA1a_best_model_headline_holdout` | 8 | `climb_v2_phase2` | single scaffold hold-out |
| `figA1b_best_model_headline_cv` | 8 | `climb_v2_phase2` | 5-fold scaffold CV |
| Table A1.a / A1.b | 10 | `climb_v2_phase2` | both |
| `figA2a_scaling_tokens` / `figA2b_scaling_unique_molecules` | 12 | `climb_v2_phase2` (2M→100M rungs) | 5-fold CV |
| `figB1p1_label_efficiency_train_test` | 14 | `climb_v2_labeleff_v2` (+ `climb_v2_phase2`) | frozen probe, label-subsampled |
| `figE1_H5_eval_ceiling` | 16 | `_eval_ceiling`, `_eval_ceiling_sup`, `climb_v2_phase2` | frozen probe + end-to-end finetune |
| `figB2_corrupted_control` | 18 | `climb_v2_phase2` (`corrupt_*` arms) | 5-fold CV |
| `figC1J1_sft_family_transfer` | 20 | `climb_v2_ablation_dedup` (+ `_tanimoto`) | 5-fold CV |
| `figI1_memorization_vs_representation` | 22 | `climb_v2_phase2` (+ `_tanimoto`) | 5-fold CV, per-molecule |
| `figC1J1_I1_combined` | 24 | reuses cells 20 + 22 | — |
| `figH1_canonical_vs_enumerated` | 26 | `climb_v2_h1` (3 seeds) | 5-fold CV |
| Figure inventory | 28 | all waves | — |
| Head-ablation table (FFN vs XGBoost) | 30 | `climb_v2_phase2` + `analysis/head_ablation` | 5-fold CV |

The exact command that produced each `<wave>/<run>/moleculenet_cv/` (only `--head`/`--featurizer`
change between model types):

```bash
# CLIMB encoder, 5-fold CV (the FFN head used everywhere)
python eval_v2.py --encoder figure_data/<wave>/<run>/encoder --tokenizer figure_data/_tokenizer \
  --output_dir figure_data/<wave>/<run>/moleculenet_cv \
  --cv_folds 5 --head_seeds 0 1 2 --pool mean --standardize zscore --head mlp --max_length 256 \
  --datasets ESOL BBBP BACE Tox21 QM7 HIV

# Single scaffold hold-out: same command WITHOUT --cv_folds (writes .../moleculenet/)

# Morgan+XGBoost anchor (no encoder):        --featurizer ecfp4   --head xgb   (drop --encoder/--tokenizer)
# Morgan+desc+XGBoost anchor:                --featurizer fp_desc --head xgb
# Head ablation (XGBoost on CLIMB embeddings): --head xgb  (see scripts/run_head_ablation.sh)
```

Helper scripts that batch these: `scripts/cv_all_budgets.sh` (all encoders × CV),
`scripts/b1_replicates_v2.sh` (label-efficiency), `scripts/run_head_ablation.sh` (FFN-vs-XGB).

## 2. Path A — regenerate all figures from the results (minutes, CPU)

```bash
python -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt
# place the results at figure_data/  (see §0)
python scripts/build_data_manifest.py --check      # confirm your figure_data == the paper snapshot
python scripts/build_figure_notebook.py            # notebook_cells/ -> climb_figures.ipynb
# execute it (embeds the figures) and export figures_out/:
MPLBACKEND="module://matplotlib_inline.backend_inline" jupyter nbconvert --to notebook \
  --execute --inplace climb_figures.ipynb
python scripts/verify_notebook_sync.py             # all-green = code + data are the paper's
```

`build_data_manifest.py --check` is the traceability gate: if your `figure_data` differs from the
snapshot the published figures were built from, it prints the exact per-cell diff instead of silently
producing different numbers.

---

## 3. Path B — reproduce the results from checkpoints (hours, GPU)

For each `<wave>/<run>` in the table above: fetch `encoder/` from the archive, run the matching
command in §1 to (re)write `moleculenet_cv/` (and `moleculenet/` for the hold-out), then follow Path A.
`eval_v2.py` uses CUDA if present, else Apple MPS, else CPU. HIV (~41k molecules) is the slow task.

---

## 4. What "reproduced" means here

- `scripts/verify_notebook_sync.py` green ⇒ on-disk `.ipynb` == `notebook_cells/` == `.notebook_generator_hash`,
  every figure cell is executed, and local `figure_data` matches `figure_data_manifest.json`.
- `audit/model_inventory.csv` is the per-run inventory (checkpoint present, eval schemes scored);
  `audit/gaps.json` empty ⇒ every release run has an archived encoder.
- Regenerate the inventory with `scripts/reproducibility_audit.py --listing <aws s3 ls output>`.

Known non-issues: the two Morgan anchors have no encoder (they are XGBoost on fingerprints);
`unsup_8M_c124` is a notation-bridge diagnostic not used in any figure; superseded waves
(`climb_v2`, `climb_v2_ablation`, `climb_v2_labeleff`) are kept for provenance only.
